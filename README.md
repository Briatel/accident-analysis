# Прогнозирование риска ДТП для каршеринговой компании

## Описание проекта
Проект направлен на разработку и оценку возможности создания системы прогнозирования риска дорожно-транспортного происшествия (ДТП) по выбранному маршруту движения. Система должна анализировать вероятность ДТП с повреждением транспортного средства (серьезнее царапины) и, при высоком уровне риска, предупреждать водителя или предлагать альтернативные рекомендации.

## Описание данных
Для обучения модели использовались исторические данные о ДТП за 2012 год (как наиболее полный и свежий доступный набор). Данные хранятся в реляционной базе данных PostgreSQL и состоят из следующих таблиц:
* **`collisions`** — информация о самом ДТП (погода, состояние дороги, освещение, тип локации, расстояние и др.).
* **`parties`** — данные об участниках ДТП (целевая переменная `at_fault` — виновность участника, тип участника, использование телефона и др.).
* **`vehicles`** — характеристики транспортного средства (возраст, тип кузова, тип трансмиссии).

**Целевая переменная:** `at_fault` (бинарный признак: 1 — водитель виновен, 0 — не виновен). 
**Фильтрация:** в анализ включены только водители автомобилей (`party_type = 1`) и инциденты с повреждениями серьезнее царапины (`collision_damage != 0`).

## Этапы решения

### 1. Загрузка и первичная обработка данных
* Подключение к базе данных через `SQLAlchemy` и загрузка таблиц.
* Проверка структуры данных, типов и первичных ключей (`case_id`, `party_number`).
* Очистка данных: удаление полных дубликатов, обработка пропусков, фильтрация аномальных значений.
* Приведение названий столбцов к единому формату `snake_case`.

### 2. Исследовательский анализ данных (EDA)
* Анализ распределения целевой переменной.
* Анализ влияния категориальных признаков на вероятность виновности.
* Построение матрицы корреляций (с использованием `phik` для смешанных типов данных) для оценки линейных и нелинейных связей.

### 3. Инжиниринг признаков и отбор
Отбор признаков проводился с учетом бизнес-требований: в модель должны входить только те данные, которые известны **до начала поездки** или могут быть получены из контекста маршрута.
* **Числовые признаки:** `vehicle_age`, `distance`.
* **Категориальные признаки:** `vehicle_type`, `vehicle_transmission`, `weather_1`, `road_surface`, `lighting`, `road_condition_1`, `location_type`, `county_location`.

### 4. Моделирование
* Разделение выборки на обучающую и тестовую (стратификация по целевому признаку).
* Создание `ColumnTransformer` для предобработки:
  * `OneHotEncoder` — для кодирования категориальных признаков.
  * `StandardScaler` — для масштабирования числовых признаков.
* Обучение и оптимизация гиперпараметров (`GridSearchCV` с метрикой `roc_auc`) для трех моделей:
  * `LogisticRegression`
  * `RandomForestClassifier`
  * `XGBClassifier`

## Интерпретация и бизнес-выводы
1. **Техническая реализуемость:** Построить модель с умеренной предсказательной способностью (ROC-AUC ~0.66) возможно на основе имеющихся исторических данных.
2. **Ключевые факторы риска:** Погодные условия, состояние дорожного покрытия и тип локации (перекресток, шоссе) вносят наибольший вклад в прогноз риска.
3. **Критическое ограничение:** Наиболее сильные предикторы аварийности, присутствующие в данных (`cellphone_in_use`, `party_sobriety`, `party_drug_physical`), являются **постфактумными**. В реальных условиях каршеринга эти данные недоступны до начала поездки без установки дополнительного оборудования (камер с компьютерным зрением или биометрических датчиков).
4. **Рекомендация:** Для внедрения системы в продакшен необходимо интегрировать API прогноза погоды и дорожных условий для конкретного маршрута, а также рассмотреть возможность сбора телематических данных в реальном времени.
